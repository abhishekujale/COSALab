# 1. Creating a CentOS Stream 9 VM

## Step 1 — Create a New Virtual Machine

Open VMware Workstation:

```text
File → New Virtual Machine
```

A popup will appear.

Select:

```text
Typical (Recommended)
```

Click **Next**.

---

## Step 2 — Select Operating System Installation

Select:

```text
I will install the operating system later
```

Click **Next**.

---

## Step 3 — Select Guest Operating System

Select:

```text
Guest OS: Linux
Version: CentOS 64-bit
```

For CentOS Stream 9, VMware may provide different options depending on the VMware version.

If CentOS Stream 9 is not listed, an appropriate 64-bit RHEL/CentOS option can generally be selected.

Click **Next**.

---

## Step 4 — Name the Virtual Machine

Give the VM a meaningful name.

Example:

```text
CentOS-Stream-9
```

Change the VM location if required.

Example:

```text
D:\VMs\CentOS-Stream-9
```

Click **Next**.

---

## Step 5 — Configure Virtual Disk

Set the virtual disk size.

Example:

```text
Maximum disk size: 80 GB
```

VMware may provide an option to:

* Store the virtual disk as a single file
* Split the virtual disk into multiple files

Then click:

```text
Next → Finish
```

> **Note:** A dynamically growing virtual disk does not necessarily consume the entire 80 GB on the host immediately. The host storage generally grows as data is written.

# 5. Disk Partitioning

From the partitioning scheme dropdown, select:

```text
Standard Partition
```

Create the following partitions:

| Mount Point |  Size |
| ----------- | ----: |
| `/boot`     |  2 GB |
| `/`         | 30 GB |
| `swap`      | 16 GB |

---

## `/boot`

Create:

```text
Mount Point: /boot
Desired Capacity: 2G
```

---

## Root `/`

Create:

```text
Mount Point: /
Desired Capacity: 30G
```

---

## Swap

Create:

```text
Mount Point: swap
Desired Capacity: 16G
```

Click:

```text
Done
```

The installer will display the changes that will be made to the disk.

Confirm the changes.

---

## Remaining Disk Space

If the virtual disk is:

```text
80 GB
```

and the partitions are:

```text
/boot → 2 GB
/     → 30 GB
swap  → 16 GB
```

Total:

```text
2 + 30 + 16 = 48 GB
```

Approximately:

```text
80 - 48 = 32 GB
```

remains unallocated.

You can use this space for:

* `/home`
* `/var`
* Another partition
* Expanding an existing filesystem

For a basic practice VM, another simple layout could be:

```text
/boot → 1–2 GB
swap  → appropriate size
/     → remaining space
```

# 7. Root Password

Go to:

```text

```

Set a strong password.

Root can:

* Install software
* Modify system configuration
* Create/delete users
* Change permissions
* Start/stop services
* Modify networking
* Access protected files

> **Be careful when working as root. A wrong command can damage the system.**

# 10. Understanding the Linux Prompt

## `kiosk`

This is the username.

Example:

```text
kiosk
```

It means the currently logged-in user is `kiosk`.

Another example:

```bash
abhishek@localhost ~ $
```

Here the username is:

```text
abhishek
```

---

## `@`

The `@` separates:

```text
username@hostname
```

Example:

```text
kiosk@localhost
```

means:

```text
Username  → kiosk
Hostname  → localhost
```

---

## `localhost`

This is the hostname of the machine.

```text
localhost
```

generally refers to the current machine.

Check the hostname:

```bash
hostname
```

or:

```bash
hostnamectl
```

---

## `~` — Tilde

The tilde represents the current user's home directory.

For example, if the user is:

```text
kiosk
```

then:

```text
~
```

usually represents:

```text
/home/kiosk
```

Therefore:

```bash
cd ~
```

takes you to:

```text
/home/kiosk
```

---

## `$` — Normal User

The `$` prompt generally indicates that you are operating as a regular user.

Example:

```bash
kiosk@localhost ~ $
```

---

## `#` — Root User

The `#` prompt generally indicates that you are operating as root.

Example:

```bash
[root@localhost ~]#
```

Therefore:

```text
$ → Regular user
# → Root user
```

# 12. Linux Filesystem

Linux follows a hierarchical filesystem structure.

The top of the filesystem is:

```text
/
```

This is called the **root directory**.

Do not confuse:

```text
/
```

with:

```text
/root
```

They are completely different.

```text
/       → Root of the entire filesystem
/root   → Home directory of the root user
```

---

# 13. Important Linux Directories

## `/bin` — Essential Commands

Traditionally:

```text
/bin
```

contained essential executable programs used by users.

Examples:

```text
ls
cp
mv
cat
echo
```

### Modern CentOS/RHEL

Modern CentOS/RHEL systems use a **usr-merged filesystem layout**.

Typically:

```text
/bin → /usr/bin
```

So `/bin` may be a symbolic link to `/usr/bin`.

Check it using:

```bash
ls -ld /bin
```

---

# 14. `/sbin` — System Administration Commands

Traditionally:

```text
/sbin
```

contained system administration commands.

Modern systems commonly use:

```text
/usr/sbin
```

and:

```text
/sbin → /usr/sbin
```

may be a symbolic link.

> The distinction between `/bin` and `/sbin` is less strict on modern Linux systems.

---

# 15. `/usr` — User-Space Programs and Data

The `/usr` directory contains a large portion of user-space programs and supporting files.

Important directories:

```text
/usr/bin
/usr/sbin
/usr/lib
/usr/share
```

Examples:

```text
/usr/bin
```

contains many standard commands.

```text
/usr/sbin
```

contains many system administration utilities.

---

# 16. `/etc` — Configuration Files

```text
/etc
```

contains system-wide configuration files.

Examples:

```text
/etc/hosts
/etc/fstab
/etc/passwd
/etc/group
/etc/hostname
/etc/ssh/
```

Important files:

| File               | Purpose                                        |
| ------------------ | ---------------------------------------------- |
| `/etc/passwd`      | User account information                       |
| `/etc/shadow`      | Password hashes and password aging information |
| `/etc/group`       | Group information                              |
| `/etc/hosts`       | Local hostname-to-IP mappings                  |
| `/etc/fstab`       | Filesystem mount configuration                 |
| `/etc/hostname`    | System hostname                                |
| `/etc/resolv.conf` | DNS resolver configuration                     |

### Remember

```text
/etc → Configuration
```

---

# 17. `/boot` — Boot Files

```text
/boot
```

contains files required during the system boot process.

Examples include:

* Linux kernel
* `initramfs`
* GRUB bootloader files

CentOS/RHEL systems commonly use:

```text
GRUB 2
```

### Remember

```text
/boot → Boot-related files
```

---

# 18. `/dev` — Device Files

```text
/dev
```

contains device files representing hardware and virtual devices.

Examples:

```text
/dev/sda
/dev/sdb
/dev/null
/dev/random
```

For example:

```text
/dev/sda
```

may represent a disk.

```text
/dev/null
```

is a special device that discards data written to it.

### Remember

```text
/dev → Devices
```

Linux follows the important concept:

> **Everything is a file.**

This is a useful model, although not every kernel object is literally an ordinary filesystem file.

# 19. `/home` — Normal Users' Home Directories

```text
/home
```

contains home directories for normal users.

Example:

```text
/home/abhishek
/home/kiosk
/home/user1
/home/user2
```

If the username is:

```text
abhishek
```

the home directory is usually:

```text
/home/abhishek
```

Shortcut:

```text

```

---

# 20. `/root` — Root User's Home

```text
/root
```

is the home directory of the root user.

Remember:

```text
/       → Entire filesystem root
/root   → Root user's home directory
```

# 21. `/proc` — Process and Kernel Information

```text
/proc
```

is a **virtual filesystem** that provides information about:

* Running processes
* CPU
* Memory
* Kernel
* System information

Examples:

```bash
cat /proc/cpuinfo
```

CPU information:

```bash
cat /proc/meminfo
```

Memory information:

```bash
ls /proc
```

You will see directories corresponding to process IDs.

> `/proc` is not a normal disk directory. Much of its information is generated dynamically by the Linux kernel.

---

```text
/srv
```

# 24. SELinux

SELinux stands for:

```text
Security-Enhanced Linux
```

It provides **Mandatory Access Control (MAC)**.

SELinux adds security controls beyond traditional Linux:

```text
User
+
Group
+
File permissions
+
SELinux security policies
```

SELinux can restrict what a process is allowed to access even when normal Unix permissions might otherwise allow access.

Modern CentOS systems expose the SELinux filesystem mainly through:

```text
/sys/fs/selinux
```

Check SELinux status:

```bash
getenforce
```

Possible results:

```text
Enforcing
Permissive
Disabled
```

For detailed information:

```bash
sestatus
```

# 25. Other Important Linux Directories

## `/tmp` — Temporary Files

Used for temporary files.

```text
/tmp
```

Applications and users can store temporary data here.

---

## `/run` — Runtime Data

```text
/run
```

contains runtime information created after boot.

Examples include:

* PID files
* Socket files
* Service runtime information

---

## `/lib` and `/lib64` — Libraries

Contain important libraries required by programs.

On modern systems, these may be linked into locations under `/usr`.

---

## `/opt` — Optional Software

```text
/opt
```

is commonly used for optional or add-on application software.

Example:

```text
/opt/myapplication
```

---

## `/media` — Removable Media

Used as a mount point for removable devices such as:

* USB drives
* CD/DVD media

---

## `/mnt` — Temporary Mount Point

Traditionally used for manually mounted filesystems.

Example:

```bash
mount /dev/sdb1 /mnt
```

---

## `/sys` — Kernel and Hardware Information

```text
/sys
```

is another virtual filesystem provided by the Linux kernel.

It exposes information related to:

* Hardware
* Devices
* Drivers
* Kernel subsystems

Common directories:

```text
/sys/block
/sys/bus
/sys/class
/sys/devices
/sys/kernel
/sys/module
```

# 26. Linux Filesystem Structure

```text
/
├── bin      → Essential user commands
├── boot     → Bootloader, kernel, initramfs
├── dev      → Device files
├── etc      → Configuration files
├── home     → Normal users' home directories
├── lib      → Libraries
├── media    → Removable media
├── mnt      → Temporary mount point
├── opt      → Optional/add-on software
├── proc     → Process/kernel information
├── root     → Root user's home directory
├── run      → Runtime data
├── sbin     → System administration commands
├── srv      → Data served by services
├── sys      → Kernel/device information
├── tmp      → Temporary files
├── usr      → User-space programs and data
└── var      → Variable/changing data
```

# 27. Absolute Path vs Relative Path

## Absolute Path

An absolute path starts from:

```text
/
```

Example:

```text
/home/abhishek/Documents
```

It specifies the complete location.

---

## Relative Path

A relative path starts from the current directory.

Suppose you are currently inside:

```text
/home/abhishek
```

Then:

```text
Documents/file.txt
```

means:

```text
/home/abhishek/Documents/file.txt
```

---

# 28. Important Path Symbols

| Symbol | Meaning                                        |
| ------ | ---------------------------------------------- |
| `/`    | Root directory                                 |
| `~`    | Current user's home directory                  |
| `.`    | Current directory                              |
| `..`   | Parent directory                               |
| `-`    | Previous directory in commands that support it |

Examples:

### Go to filesystem root

```bash
cd /
```

### Go to home directory

```bash
cd ~
```

### Go to parent directory

```bash
cd ..
```

### Stay in current directory

```bash
cd .
```

# 30. Root vs Normal User

Linux provides different levels of privileges.

## Normal User

Prompt:

```text
$
```

Example:

```bash
kiosk@localhost ~ $
```

A normal user generally cannot modify protected system files without elevated privileges.

---

## Root User

Prompt:

```text
#
```

Example:

```bash

```

Root has extensive administrative privileges.

Root can:

* Install software
* Modify system configuration
* Create/delete users
* Change permissions
* Start/stop services
* Modify networking
* Access protected files

Therefore:

> **Use root privileges only when necessary.**

## Key Corrections from the Original Notes

A few points from the initial notes needed updating for modern CentOS Stream 9:

1. **`/bin` and `/sbin`**

   * Modern CentOS/RHEL uses a usr-merged layout.
   * `/bin` commonly points to `/usr/bin`.
   * `/sbin` commonly points to `/usr/sbin`.

2. **`/srv`**

   * It is intended for **data served by services**, not simply "third-party software services."

3. **SELinux**

   * SELinux means **Security-Enhanced Linux**.
   * It provides **Mandatory Access Control (MAC)**.
   * Modern systems expose its filesystem mainly through `/sys/fs/selinux`.

4. **`/proc`**

   * It is a **virtual filesystem**, not a normal directory containing permanent files.

5. **`/sys`**

   * It is another virtual filesystem providing kernel/device information.

6. **80 GB disk**

   * Creating an 80 GB virtual disk does not necessarily mean 80 GB is immediately consumed on the physical host when using a dynamically growing virtual disk.
